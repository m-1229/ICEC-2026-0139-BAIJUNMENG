# 声学超标自动提醒光效逻辑设计

> ICEC-2026-0139 · 课题 06 校园昼夜声学噪声地图测绘
> 配套实现：`src/light_controller.js`　在线演示：`index.html` → 第 05 节

---

## 1. 设计目标与约束

校园里"吵"是一个看不见的量：学生不会盯着分贝数看，管理员也不可能 24 小时守在声级计旁边。
本设计的核心命题是——**把不可见的声音强度，翻译成一眼可读、无需文字、远距离成立的光信号**。

四条硬约束决定了方案形态：

| 约束 | 含义 | 应对 |
| --- | --- | --- |
| 必须远距离可读 | 3–8 m 外不看屏幕就知道"现在超了" | 用**颜色**做一级编码，不依赖数字与文字 |
| 不能造成新的干扰 | 灯本身不能变成光污染、不能干扰上课 | 亮度分级 + 夜间降亮 + 禁用高频闪烁 |
| 不能误报 | 一次拍桌、一声喊叫不该触发红灯 | 能量平均 + 回差 + 最小驻留 + 峰值单独处理 |
| 必须与地图一致 | 现场灯色要和地图上该点位的颜色对得上 | 阈值分级表为唯一真源（single source of truth） |

## 2. 系统组成

```
        ┌──────────────┐   I²S    ┌──────────────┐   PWM    ┌──────────────┐
声波 →  │  MEMS 麦克风  │ ───────→ │  MCU（ESP32） │ ───────→ │  WS2812B 灯柱 │ → 人眼
        │  A 计权前置   │          │  判据 + 状态机 │          │  12 颗 RGB    │
        └──────────────┘          └──────┬───────┘          └──────────────┘
                                           │ Wi-Fi / MQTT
                                           ↓
                                   ┌──────────────┐
                                   │ 噪声地图后端   │  热力图 · 15 组数据 · 时间序列
                                   └──────────────┘
```

- **采集**：MEMS 麦克风 + A 计权，采样率 ≥ 8 kHz，每 200 ms 输出一个 1 s 窗的有效值。
- **计算**：MCU 内完成能量平均、峰值保持、阈值判定与状态机，**不依赖云端**（断网仍可用）。
- **输出**：12 颗 WS2812B 串联成 1.2 m 灯柱，5 段分区显示（对应 L0–L4），也可整柱同色。
- **上报**：每 10 s 一条聚合记录（Leq / Peak / 状态 / 温度），异常事件附带 30 s 原始波形。

## 3. 分级阈值：以"超标量 Δ"为唯一自变量

不同点位的限值不同（图书馆 50、食堂 60、主干道 70…），若按绝对声级分级，同一套灯在食堂永远红灯、在图书馆永远绿灯。
因此分级自变量取**相对量**：

```
Δ = L_Aeq,1s − L_limit,zone      （L_limit 随点位功能区与昼/夜自动切换）
```

| 等级 | 名称 | 判据 | 颜色 | 语义 |
| :--: | --- | --- | --- | --- |
| **L0** | 达标 | Δ ≤ 0 | 🟢 `#16a34a` | 安静，可以正常活动 |
| **L1** | 轻微超标 | 0 < Δ ≤ 5 | 🟡 `#eab308` | 略吵，注意音量 |
| **L2** | 明显超标 | 5 < Δ ≤ 10 | 🟠 `#f97316` | 明显偏吵，需要干预 |
| **L3** | 严重超标 | 10 < Δ ≤ 15 | 🔴 `#dc2626` | 严重超标，立即处置 |
| **L4** | 极重超标 | Δ > 15 | 🔴 `#b91c1c` + 白光 | 极端噪声，强制警示 |

功能区限值取自本次测绘的判定基准（`analysis/analyze.py` 中 `ZONES`）：

| 点位 | 功能区 | 昼间 | 夜间 |
| --- | --- | :--: | :--: |
| 图书馆 | 1 类区 · 阅览区（室内） | 50 | 45 |
| 食堂 | 2 类区 · 就餐区（室内） | 60 | 50 |
| 主干道 | 4a 类区 · 交通干线两侧 | 70 | 55 |
| 操场 | 1 类区 · 运动场（室外） | 55 | 45 |
| 实训室 | 3 类区 · 走廊（室内） | 65 | 55 |

> 5 dB 一档的设计依据：人耳对声级变化的可辨阈约 1–3 dB，"明显变吵"约 5 dB，10 dB 主观响度翻倍。
> 分级与主观感受对齐，灯色变化才符合直觉。

## 4. 三路判据融合

只用 1 s 能量平均会被瞬态冲击欺骗（拍桌 100 dB 但仅 0.2 s，能量被摊薄）；
只用峰值又会因偶发噪声狂闪。因此并行三路，取最严：

| 判据 | 窗口 | 作用 | 权重处理 |
| --- | --- | --- | --- |
| `Leq1s` | 1 s 滑动 | 快速响应，主判据 | 直接映射等级 |
| `Leq60s` | 60 s 滑动 | 稳态暴露，防止长期超标被瞬时安静掩盖 | 取 `max(等级(Leq1s), 等级(Leq60s))` |
| `Peak` | 1 s 峰值保持 | 捕捉冲击类噪声 | `Peak − limit ≥ 20 dB` → 强制升一级，锁定 5 s |

能量平均必须用**对数域**，不能算术平均：

```js
// 正确：能量域平均
Leq = 10 * Math.log10( Σ(10 ** (Li / 10)) / n );
// 错误：算术平均（会把 80 dB 和 40 dB 平均成 60 dB，实际能量上接近 77 dB）
```

## 5. 状态机与去抖

```
        Δ 跨档上升（立即）                      Δ 回落（连续 3 s 且驻留 ≥2 s）
  L0 ──────────────────→ L1 ──→ L2 ──→ L3 ──→ L4
   ↑                                            │
   └────────────── 降级路径（经回差线与驻留时间）──┘
```

三条防抖规则缺一不可：

1. **回差（Hysteresis）**：回落判据用 `触发线 − 3 dB`，而不是触发线本身。
   若临界噪声正好在 60 dB 抖动，用同一阈值会导致灯每秒切换数十次（视觉上极其烦躁）。
2. **最小驻留（Dwell）**：任一状态至少显示 2 s 才能改变，保证"看得清"。
3. **下降延迟（Hold）**：连续 3 s 低于回落线才降级；升级则**零延迟**——变吵必须立刻可见。

不对称设计是刻意的：**快升慢降**。安全提示宁可多亮 3 秒，也不能漏报。

### 5.1 夜间模式

| 项 | 昼间（06:00–22:00） | 夜间（22:00–06:00） |
| --- | --- | --- |
| 亮度 | 按 Δ 线性提升至 100% | **× 0.45**，上限 45% |
| 最高等级 | L4 | **L3**（禁用爆闪） |
| 闪烁频率 | ≤ 2 Hz | ≤ 0.6 Hz，仅慢呼吸 |

依据：夜间人眼暗适应后对光强敏感度显著提高，且校园夜间照明需避免对宿舍、周边居民造成光干扰。
**声学设备不该制造光污染**——这是本设计的一条自我约束。

### 5.2 故障与降级

| 故障 | 表现 | 灯效 |
| --- | --- | --- |
| 麦克风开路/短路 | 自检失败 | 🟡 0.1 Hz 极慢呼吸（"我坏了"） |
| 网络中断 | MQTT 心跳超时 | 🟣 紫色常亮（本地仍正常判级，仅不上报） |
| 供电不足 | 电压 < 4.5 V | 🟢 绿灯微亮（降级为最低功耗模式） |

故障态与超标态**必须视觉可区分**：所以用紫色（正常分级里不出现的颜色）+ 极慢频率。

## 6. 光效映射表

亮度不是恒定值，而是随偏离量连续变化——**越吵越亮**，强度本身也是信息：

```js
brightness = clamp(0.35 + 0.65 * min(1, Δ / 20), 0.35, 1.0)   // 夜间再 × 0.45
```

| 等级 | 颜色 | 波形 | 频率 | 占空比 | 昼间亮度 | 夜间 |
| :--: | --- | --- | :--: | :--: | :--: | --- |
| L0 | `#16a34a` 绿 | 常亮 | — | 100% | 20% | 9% |
| L1 | `#eab308` 黄 | 正弦呼吸 | 0.25 Hz | 100% | 45% | 20% |
| L2 | `#f97316` 橙 | 正弦呼吸 | 0.60 Hz | 100% | 75% | 34% |
| L3 | `#dc2626` 红 | 方波脉冲 | 1.20 Hz | 50% | 95% | 43% |
| L4 | `#b91c1c` 深红 | 爆闪 + 白光交替 | 2.00 Hz | 30% | 100% | 禁用 → L3 |

**编码维度总结**：颜色 = 等级（离散，5 档）；频率 = 紧迫度（连续上台阶）；亮度 = 偏离量（连续）；占空比 = 刺目程度。

## 7. 与噪声地图的联动

现场灯光和线上地图共用同一张阈值表，保证"看到的灯"和"看到的图"永远一致：

- 地图上 5 个点位按当前状态着色，超标的点位做与灯柱同频的脉冲动画；
- 点击点位展开该组 15 组实测数据、雷达图与最近 10 min 的 Leq 曲线；
- 15 组测绘数据（`data/metrics.json`）作为地图底图的**静态层**，实时数据作为**动态层**叠加；
- 异常事件（≥ L3 持续 > 10 s）在地图上留下时间戳标记，支持事后溯源。

## 10. 为什么这样设计（答辩要点）

1. **以 Δ 而非绝对声级分级**——一套固件通用于 5 个不同限值的点位，部署时只改一个参数。
2. **颜色编码离散化 + 强度编码连续化**——离散保证"一眼可读"，连续保证"越吵越明显"，两者不冲突。
3. **快升慢降的不对称状态机**——把"漏报"与"闪烁"这两个对立缺陷同时压到最低。
4. **夜间主动降级**——承认提醒系统本身也是环境负荷的一部分，这是很多方案会忽略的自我约束。
5. **现场与地图同源**——避免"灯红了图还绿"的信任崩塌，这一点比任何单个参数都重要。
